Every route here needs a workspace admin (the organization's Owner counts as one); EDITOR and READER get FORBIDDEN. These routes take the cookie only — a token can never list, mint or revoke tokens. The secret is shown once, at the mint, and never again.

Tokens — GET /workspaces/:id/tokens

Live tokens, newest first; a revoked one is never listed. An expired one still is, and still counts toward the plan's limit (free 2, starter 5, growth 20, scale 50) until revoked. Last used is written at most once a minute.

Mint a token — POST …/tokens

Answers 201 with secret this one time. Scopes only narrow: a USER token acts as its maker and shrinks if they are demoted; a SERVICE token acts as a workspace ADMIN reaching every project, and only someone who reaches every project may make one. No Idempotency-Key: a second click mints a second token.

Try it — Authorization: Bearer <secret>

Sends the secret as a bearer to a route that admits tokens. The cookie still travels, but a bearer always wins, and a bad one is refused outright (401), never retried as the cookie. A scope that does not cover the route gets 403. The X-RateLimit-* headers are not exposed to this page by CORS; read them with curl.

Rate limit — GET …/rate-limit

This clock minute's token use. Each token may make 120 a minute and the workspace 600; only token requests count, never the cookie. windowUsedPct is the workspace's share of its 600.
