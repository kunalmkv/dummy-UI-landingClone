Codes come from an authenticator app scanning the QR below. Every six-digit code works once: after using one, wait for the app to show the next before sending another.

Finish a sign-in

POST /auth/mfa/verify — when a sign-in (password, magic link or Google) answers mfaRequired, you are not signed in yet: only a challenge cookie is set. A code from the app or one backup code finishes it. Five wrong codes destroy the challenge.

POST /auth/mfa/abandon — throws the challenge away.

Turn two-factor on

POST /auth/mfa/setup then POST /auth/mfa/enable. Setup alone turns nothing on — only a real code from the app does, so a bad scan cannot lock you out. Setup again before enabling to start over.

Backup codes

POST /auth/mfa/regenerate-backup-codes — needs the password. The old set dies at once. Codes are shown once (here and after enabling) and cannot be read back.

Turn two-factor off

POST /auth/mfa/disable — needs the password and a working code, so a stolen session alone cannot remove the second factor. ⚠️ The API takes an authenticator code here; a backup code is refused.

Confirm identity

POST /auth/identity/confirm — proves it is still you before one high-impact action. Send the password, or a code if two-factor is on. The grant is tied to this session and the one action, lasts 5 minutes and is spent by that action. Every check, right or wrong, counts toward 10 per 15 minutes.
