Address under test

A real, verified account. The lockout lasts 15 minutes and doubles each time, so use a fresh account per run. Every check below uses this address unless it says otherwise.

1 · Lockout

POST /auth/session/login with wrong passwords until the API locks the address (five in 15 minutes). Each wrong answer carries attemptsRemaining; the lock carries retryAfterSeconds — seconds, never a timestamp.

2 · Magic link while locked out

POST /auth/magic-link/request is not gated by the lockout, so someone locked out of the password route still has a way in. Opening the link (POST /auth/magic-link/consume) signs in and clears the lockout — try the right password again after.

3 · Cooldowns

Send twice within a minute: the second is accepted but sends nothing. Magic link and verification resend return resendAfterSeconds to count down; forgot-password's cooldown is silent.

4 · A code with no challenge

POST /auth/mfa/verify with 123456 and no sign-in waiting. Must be 401: the challenge cookie says which sign-in is waiting, so a code alone proves nothing. ⚠️ If a challenge is live in this browser this spends one of its attempts — abandon it on two-factor first.

5 · Anti-enumeration, side by side

The same request for the address under test and for one with no account, then the two responses compared. resendAfterSeconds is a countdown, so it is masked; any other difference tells a stranger the account exists. ⚠️ The login option spends one of the address's five attempts.
