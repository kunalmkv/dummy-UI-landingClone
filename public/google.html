checking…

The server verifies every ID token against Google's keys, with the audience pinned to its own GOOGLE_CLIENT_ID. If that is not configured, or the token was minted for another client id, every call below answers 401 "could not be verified" — which is itself worth seeing. While the consent screen is in Testing, only listed test users get a token at all.

Get an ID token

The button comes from Google's script and fills the token box. It must use the same client id the API is configured with. No button? Paste a token by hand, or send any text to see the refusal.

Sign in or sign up

POST /auth/google/sign-in — four answers on a 200: a session, mfaRequired, a direct sign-up (a new Google account gets its organization named for it — send an organization to choose the name) or linkRequired (the address already has a password account; sign in with the password and link below).

Link and unlink

POST /auth/google/link needs the password as well as the session, so owning a matching Google address is never enough to claim an account. POST /auth/google/unlink is refused when Google is the only way in.
